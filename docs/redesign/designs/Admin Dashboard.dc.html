Where each journey starts
Home → a top-three model → profile → change the profile's own month → Performance → an order.
Models → Invitations → an application → verify the code and set terms → Approve.
Products → a product → Feature request → Received and On the way previews → Save → Active requests filter.
A profile → Payments → Edit terms → pick January and February → apply → pick March and April → apply again.
Targets → Set requirements, save, then Record achieved — the two stores stay separate.
Payments (October) → a model → Where to send it → Approve → Record payment → receipt.
Home notice “Late failed order” → absorb or carry → the destination month's breakdown.
Payments (November) → Ziad Nabil → no transfer due, EGP 260 carried on.
Unresolved business choices
Content-progress threshold. No rule decides when a model is behind this week. Home lists monthly shortfalls and missing records for review only; the threshold is still to be agreed.
InstaPay field naming. The model app labels one field “Account number” while the repository stores a phone number plus its submitted link. This prototype shows both as separate fields; the mapping question stays open.
Sample launch boundary. January and February 2026 are treated as prelaunch fixtures: settled, no receipts imported, no funding requirement. The real boundary is not an agreed business decision.
Historical receipts. Reconstructed earnings only. No transfer records are invented for those months.
Prototype scope
Local sample data only. Nothing reaches Shopify, sends an invitation or records a real transfer.
Product photography and transfer receipts are marked placeholders awaiting real assets.
Approving a month freezes its calculation; there is no reopening action.
Earlier snapshots kept for comparison: Admin Products, Affiliate Portal v3.
